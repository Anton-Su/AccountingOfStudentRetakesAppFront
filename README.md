# Accounting of Student Retakes App

Мобильное приложение для управления и учета пересдач студентов. Приложение позволяет отслеживать информацию о пересдачах студентов, хранить и обновлять данные.

## 🎯 Основные возможности

- 📱 Современный интерфейс на основе Jetpack Compose
- 🔄 Синхронизация данных через сетевые запросы
- 💾 Локальное хранилище данных с Room
- 🔐 Безопасное хранение настроек и токенов
- 📡 HTTP-клиент на базе Ktor

## 🚀 Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/Anton-Su/AccountingOfStudentRetakesAppFront.git
cd AccountingOfStudentRetakesApp
```

### 2. Открытие проекта
- Откройте Android Studio
- Выберите **File** → **Open** и укажите путь к папке проекта
- Android Studio автоматически синхронизирует Gradle

### 3. Использование Gradle Wrapper
Проект использует Gradle Wrapper для обеспечения согласованности версий Gradle.

```bash
# На Windows
./gradlew.bat build

# На Linux/Mac
./gradlew build
```

### 4. Запуск приложения
- Подключите Android устройство (или запустите эмулятор)
- Нажмите **Run** или используйте комбинацию клавиш **Shift + F10**

## 🔧 Основные компоненты

### Activities
- **MainActivity**: Главная activity приложения с Compose UI

### Сетевое взаимодействие
- Ktor HTTP-клиент с поддержкой логирования и аутентификации

### База данных
- Room ORM для работы с SQLite
- KSP для кодогенерации во время компиляции

### Хранилище данных
- DataStore Preferences для безопасного хранения пользовательских настроек

### Архитектура данных
```
┌─────────────────────┐
│   Android App       │
│  ┌───────────────┐  │
│  │  Room (SQLite)│  │
│  │   (локальная) │  │
│  └─────┬─────────┘  │
│        │ синхронизация
│        │             │
└────────┼─────────────┘
         │ HTTP/Ktor
         ↓
   ┌──────────────┐
   │ Backend API  │
   │ (сервер)     │
   └──────┬───────┘
          │
          ↓
    ┌──────────────┐
    │ Neon         │
    │ PostgreSQL   │
    └──────────────┘
```

### Использование в приложении

Приложение использует следующий поток работы с данными:
1. Данные сначала сохраняются локально в Room
2. Ktor клиент отправляет данные на Backend API
3. Backend синхронизирует данные с PostgreSQL (Neon)
4. При необходимости приложение может получить актуальные данные с облака

### Примеры переменных окружения (для Backend)

```env
DATABASE_URL=postgresql://user:password@host/database
NEON_API_KEY=your_neon_api_key
```

## 👥 Роли пользователей

Система поддерживает несколько ролей пользователей, каждая из которых имеет определенные функции и доступ:

| Роль | Описание | Функции |
|------|---------|---------|
| 👨‍🎓 **STUDENT** | Студент | Просмотр доступных пересдач, запись на пересдачу, просмотр своих долгов, отслеживание рейтинга долгов |
| 👨‍🏫 **TEACHER** | Преподаватель | Управление пересдачами по своим дисциплинам, выставление оценок, просмотр списка студентов |
| 👨‍💼 **ADMIN** | Администратор | Полный доступ к системе, управление учителями и дисциплинами, просмотр всех пересдач |

### Данные пользователя

Каждый пользователь имеет следующую информацию в системе:
- **ID**: Уникальный идентификатор
- **Role**: Роль в системе (см. таблицу выше)
- **Личные данные**: Имя, отчество, фамилия
- **Gender**: Пол пользователя
- **Age**: Возраст
- **Email**: Электронная почта

### Авторизация

При входе в приложение пользователь проходит аутентификацию, и система автоматически определяет его роль. В зависимости от роли загружаются соответствующие экраны и функции.
